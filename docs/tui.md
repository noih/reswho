# 基本 TUI

stdin 與 stdout 都是 TTY 時，`reswho` 自動開啟 TUI；其他情況預設一次性 Markdown。`--tui` 要求終端機，`--md`／`--json` 明確指定一次性輸出。

沿用既有 snapshot、分類與容器 adapter，不另作名稱猜測。`--from` 選擇根節點，`--depth` 控制初始展開深度，之後仍可手動往下展開。`--sort cpu|memory|uptime|name` 設定初始排序（預設 memory），與 Markdown／JSON 共用比較規則。

全機視圖直接從分類開始，不顯示重複的 Resources 根列；整機用量與程序數保留在頂端。全機 `--depth 0`／`1` 仍顯示收合的分類，預設 `2` 展開到其下一層。System 若只有一個 System services 包裝，則直接顯示其執行檔群組／程序。這只改變 TUI 呈現，snapshot、Markdown／JSON 與原有 group ref 均保留；明確 `--from` 指定的其他根節點仍顯示。

| 按鍵 | 操作 |
| --- | --- |
| ↑／↓、k／j | 選取上一／下一列 |
| ←／h、→／l | 收合或父層、展開或子層 |
| Enter／Space | 展開／收合 |
| d | 選取程序時開啟詳情頁；Esc 或 d 返回列表 |
| Home／End、PgUp／PgDn | 首尾列、移動十列 |
| c／m／u | 同層 CPU／RAM／uptime 降序排列 |
| n | 同層名稱自然升序排列 |
| / | 搜尋名稱、PID、ref、路徑；Enter 保留，Esc 清除 |
| a | 容器 all／active 切換；保留未知狀態 |
| [／] | 左右捲動底部路徑列 |
| r／p | 立即刷新／暫停自動刷新 |
| ?、q／Ctrl-C | 說明、退出 |

搜尋保留匹配項目的父層；匹配群組時顯示其子樹。清除搜尋會恢復原展開狀態。篩選只影響顯示，不重算 totals；容器與主機資源維持不同計算範圍。Age 是程序啟動至今的時間，群組為最老成員，並非持續忙碌時間。`?` 表示未知，`-` 表示不適用，`>=` 表示部分已知值。

名稱排序忽略大小寫，連續ASCII數字比較完整數值，因此 `1, 2, 3, 10, 11`、`node2, node10`、`v2.3, v2.11` 依自然順序排列。相同數字片段的短寫法先，例如 `2` 在 `02` 前；不以固定寬度整數解析，長數字不溢位。相同名稱以 ref 穩定排序，不改父子層級，切換排序與刷新都保留選取。

排序、刷新或篩選重排列項目時，若原選取身分仍存在，捲動位置會盡量讓它留在畫面原本那一列；靠近列表邊界或視窗變小時，以保持選取可見為優先。一般上下移動不鎖定畫面列，Home／End 仍可跳到首尾。原項目消失時退到仍可見的父層；沒有可用父層才選第一列，空結果則不選取任何列。

數值依列上口徑降序排序：程序用自身用量，群組用所屬範圍合計，部分合計使用已知下界；全未知／不適用置後。同值以 ref 穩定排序。程序列不以子樹合計取代自身用量。

頂端 `Host CPU` 為整機0–100%用量；表格 `CPU/core` 以單一核心100%計算，程序與群組可以超過100%。`>=` 表示部分成員不可讀，顯示的是已知用量下界，不能直接與整機CPU百分比相比。

資源樹使用完整寬度，底部 status bar 顯示選取程序的 cwd／exe，或 app／專案／bin 的已知路徑；容器保留 project、candidate、bind 的來源標籤。沒有路徑時顯示 `Path —`，不從名稱猜測。長路徑可用 `[`／`]` 捲動，切換選取時回到開頭。錯誤仍在底部提示；程序可按 `d` 查看詳情，亦可用 `--md --from REF` 或 `--json --from REF` 查詢。

列表名稱不重複附加 `[app]`／`[bin]` 等分類標記；選取後在底部狀態列顯示 `app · group:…`，有錯誤時優先顯示診斷。程序仍保留 PID，Markdown／JSON 的分類標記與欄位不變。

底部平常與暫停時都顯示 `r refresh`，讀取失敗時顯示 `r retry`；`?` 保留快捷鍵說明。`r` 仍可隨時手動更新一次，不解除暫停；執行中在原提示位置顯示 `refreshing`／`retrying`，完成後恢復提示。若已有採集進行中，沿用該次結果，不排入重複查詢。一般自動刷新不顯示進度文字；PID 已消失或身分失效的詳情頁不提供重試。

每輪採集完成兩秒後再採下一輪，同時最多一輪。採集在背景執行，刷新保留群組展開與選取；程序身分包含 PID 與啟動時間。程序消失或 PID 重用時退回仍存在的父層；若 `--from pid:…` 本身失效，保留舊資料並標示 STALE，不自動轉向新程序。

不另設程式標題列；全機程序數放在 Host CPU／RAM 摘要列。排序工具列只在暫停或錯誤時加上狀態，不切換 live／collecting，也不顯示距上次刷新的秒數。畫面只在資料、操作、視窗大小或首次載入動畫改變時重畫。首次採集先顯示表格、工具列與 status bar，在列表中央顯示 `Loading resources...` 與約250ms更新的 spinner，完成後換成資源列並停止動畫；失敗時顯示錯誤，等待中仍可退出。Docker metadata 與用量每輪重新查詢，不使用跨輪快取。這不改變兩輪之間的等待時間。

啟動時將 alternate screen 切換與首次完整 loading 繪製包在同一個 synchronized update，避免支援此協定的終端機先呈現空白畫面。同步區段只包含初始化與首次繪製，不等待資源採集；之後仍以事件式差異重畫。初始化或繪製失敗時會嘗試結束同步更新並還原 terminal；不支援協定的終端機仍可能顯示切換過程。

退出會取消採樣等待與 Docker 查詢，回收自身建立的查詢程序，還原 terminal。取消是協作式的，已進入的原生系統／檔案查詢須先返回。此版本沒有停止服務、權限提升、歷史觀測或 Review 判定。

程序詳情是按需開啟的完整頁面，保留頂部系統摘要並替換列表，底部只顯示詳情操作。標題用青色、欄位用淡色、正文使用終端機預設色；PID 僅顯示於頁面標題。顯示命令、script/JAR 入口、cwd/exe、PPID/UID、網路端點及歸類依據；命令沿用 `[filtered]` 規則與限制。群組、容器與 Unreadable 合併列不開啟程序詳情。

開啟後顯示 `Loading command...`，使用既有單一背景採集器查詢；若已有一輪採集中，先處理該結果，再補查選取 PID 的命令。命令僅在詳情頁開啟期間隨正常刷新查詢，關閉後不再要求，重新開啟時再次查詢。暫停時開啟仍會查詢一次；詳情頁內 `r` 可手動刷新、`p` 切換自動刷新。採集中保持上一份結果，整輪失敗會清除詳情內容並顯示錯誤。

詳情頁固定 PID 與啟動時間。程序消失、身分未知或 PID 重用時停止該詳情頁的命令查詢並顯示原因，不轉向新程序；需關閉並重新選取。列表自身仍依原規則刷新。初始身分無法確認的程序只顯示已知資料與原因，不查詢命令。

詳情內 ↑/↓、j/k、PgUp/PgDn 捲動，Home/End 到首尾。長命令與路徑依終端機寬度折行，續行縮排；底部行數範圍依折行後的畫面列計算。歸類層級合併為 `Applications → App → …`，其他路徑、bundle 與依據另列；完整 group ref 保留於 Markdown／JSON。Esc/d 返回原選取與列表捲動位置；刷新或 resize 仍以維持選取可見為準，已消失的列無法保留。Enter、左右鍵、排序、搜尋等列表按鍵不作用於詳情頁，q/Ctrl-C 仍可直接退出並還原終端機。
